# The status shows the approval

| Status | Meaning |
| --- | --- |
| `draft` | The owner did not approve it yet. Follow it, but ask when it blocks you. |
| `approved` | The owner approved it. Follow it. |
| `replaced` | A different rule replaces it. That rule names it in `replaces`, and `replaced_by` names that rule. |
| `removed` | The rule is not in force. The file stays, so that the number stays taken. |

Only the owner must set `approved`. An agent must set it only after the owner approved the spec
in words.

A rule with `status: replaced` must be in `replaces` of a rule with the status `draft` or
`approved`. Its `replaced_by` must list each rule of the same repository that names it in
`replaces`, and no other rule.

Reason: The status tells every reader if the owner agrees with the rule. The new rule names the
old rule, because the copy of a different repository must not change (000048). In the same
repository, the old rule also names the new rule, so that a reader of the old rule finds the
rule in force.

Test: `scripts/check_specs.py` checks the value, `replaces` and `replaced_by`. A review checks who set `approved`.
