# The rule ID has kind, path and number

The rule ID must have the form `<kind>/<area>/<topic>/<number>`:

- `<kind>` is `F` (functional), `NF` (non-functional), `P` (protocol), `U` (structure), `S`
  (style), `C` (convention), `W` (workflow), `A` (agent) or `D` (decision).
- `<area>/<topic>` is the folder path of the file below its kind folder.
- `<number>` is the six-digit number from the file name.

Examples: `F/meetings/voting/000024`, `C/specs/format/000012`, `U/specs/model/000040`.

The file must not hold the full rule ID. The ID follows from the file path.

Reason: The ID tells the reader the kind and the place of a rule. It stays readable without a
tool.

Test: `spezi check`: the file path gives an ID that matches
`^(F|NF|P|U|S|C|W|A|D)(/[a-z0-9-]+)+/[0-9]{6}$`.
